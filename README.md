# OpenShadow

**中文版** | [英文版](README_EN.md)

> **Shadow 持有连续性。**  
> 模型和运行时可以替换，属于用户的长期状态不应该随之消失。

OpenShadow 是一个**本地优先、运行时无关的个人 AI 连续性与控制层**。

它不试图成为另一个“大而全”的智能体，而是把身份、记忆、任务、能力、规则、历史与世界状态从具体模型和智能体中解耦出来。Hermes、DSH、Claude、Codex 以及未来的新运行时都只是可替换的推理与执行资源。

## 为什么需要 OpenShadow

模型更新很快，但人的生活、项目和经验是长期连续的。今天大多数个人 AI 系统仍然把状态绑定在某个产品、会话或框架里，因此换模型、换智能体、换设备，往往意味着重新建立上下文、迁移工具和恢复配置。

OpenShadow 关注的不是“怎样再做一个更聪明的助手”，而是：

> **如果未来十年模型、智能体框架和交互方式不断变化，哪些东西应该一直留下来？**

答案是那些真正属于用户、难以重新获得的长期资产：

- 身份、偏好、约束与信任边界；
- 正在进行的任务、项目状态与决策历史；
- 可追溯的记忆、原始证据与任务经验；
- 已经接入的设备、服务、工具与自动化能力；
- 对数字世界和物理世界的当前认知；
- 长期形成的规则、流程与权限体系。

这些资产应该能够被下一代模型继续使用，而不是随着上一代产品一起被丢弃。

## 核心设计

### 用户持有连续性，运行时只负责执行

任务、记忆、规则、历史和能力的长期事实源由 Shadow 持有。运行时可以拥有临时会话、规划过程和内部上下文，但不能成为用户持久状态的唯一所有者。

因此，更换 Hermes、DSH 或未来的新运行时，应该更像更换一个执行引擎，而不是迁移整套个人 AI。

### Shadow 是稳定的“薄腰”

越容易被技术浪潮替换的东西，越应该远离核心；越属于用户本人、越难重新获得的东西，越应该靠近核心。

模型、提示词、检索引擎、交互界面和智能体框架可以快速变化，而核心契约、个人状态、原始历史和治理规则尽量保持稳定。理想情况下，接入新一代技术只需要增加适配器或替换外围实现，而不需要迁移个人数字生活。

### 系统围绕事件和世界状态运行，而不是围绕聊天窗口运行

Shadow 持续接收邮件、日历、文件、服务器、家庭设备等事件，并把“发生了什么”投影成“现在是什么状态”。任务可以由用户发起，也可以由事件、调度或条件变化触发。

因此，即使删除聊天界面，Shadow 仍然应该能够维护世界状态、恢复等待任务、调用运行时、执行能力并记录结果。

为了降低全天候运行成本，系统可以使用确定性规则、极小本地 `Pulse` 和按需唤醒的大模型进行分层处理；这是一种运行优化，而不是 Shadow 的所有权边界本身。

### 任务属于 Shadow，并可以跨运行时语义接力

Shadow 保存规范化任务、任务产物和语义检查点。运行时失败、升级或被替换时，不迁移隐藏思维链或私有内部状态，而是迁移可验证的任务语义：目标、已知事实、决策依据、已完成工作、任务产物、剩余工作和副作用状态。

这使同一个长期任务可以由不同运行时在不同阶段继续执行。

### 记忆不是“把历史全部向量化”

Shadow 将记忆分成三层：

```text
原始证据
   ↓
规范化记忆
   ↓
可重建的索引与派生层
```

原始证据负责保留事实，规范化记忆负责表达当前可追溯的认知，向量索引、摘要、图结构等都只是可以重建的派生结果。

记忆调取也不默认等于向量相似度前若干条。Shadow 根据当前任务产生明确的记忆需求，优先使用结构化、时间、实体关系等检索路径；必要时可以继续回溯原始历史，而不是被早期摘要永久限制。

### 能力属于用户，动作必须经过统一治理

邮箱、日历、服务器、家庭设备和文件系统等一旦接入 Shadow，就成为可被多个智能体复用的标准能力，而不是某一个智能体的私有工具。

所有具有现实副作用的动作都经过统一的规则、审批、幂等与审计链路：

```text
模型提出动作
     ↓
Shadow 判断权限与风险
     ↓
审批 / 幂等 / 执行台账
     ↓
能力提供者执行
```

这样，即使运行时崩溃后重新执行任务，也不应该重复发送邮件、重复创建日历或重复执行其他已经完成的现实动作。

### 可替换不仅意味着“能接入”，还意味着“能升级”

运行时、记忆引擎和能力提供者都应该拥有明确的替换边界。新的运行时可以先进行兼容性检查、历史任务回放和灰度验证，再逐步晋升；出现问题时可以回滚，而用户的记忆、任务、能力和规则无需整体迁移。

OpenShadow 追求的是较低的**升级吸收成本**：新技术主要改变适配层，而不是不断重写核心。

> **一次接入，持续复用；一次积累，被未来所有智能体继承。**

长期来看，OpenShadow 希望把 AI 使用从一种持续消费的服务，逐渐变成一种能够积累记忆、能力、经验和治理规则的**个人数字基础设施**。

> **十年后模型已经完全不同，但你的 AI 不需要重新认识你。**

## 架构概览

```text
人 / 数字世界 / 物理世界
          │
          ▼
交互与事件入口
聊天 · 语音 · 邮件 · 日历 · 文件 · 设备 · 服务器
          │
          ▼
┌──────────────────────────────────────────┐
│              SHADOW CORE                 │
│          连续性与控制层                   │
│                                          │
│ 身份 / 规则      事件 / 世界状态          │
│ 任务 / 检查点    记忆策略 / 记忆代理器     │
│ 上下文编译器     运行时接口 SRI            │
│ 能力网关 / 台账  调度器 / Pulse            │
│                                          │
│ 长期资产：                                │
│ 记忆 · 任务 · 能力 · 规则 · 历史 / 状态   │
└──────────────────────────────────────────┘
          │
          ├─ 可替换运行时
          │  Hermes · DSH · Claude · Codex · 未来运行时
          │
          ├─ 可替换记忆引擎
          │  Mem0 · LangMem · Graphiti · 未来引擎
          │
          ├─ 能力提供者
          │  家庭 · 电脑 · 服务器 · 文件 · 邮件 · 日历 · 网络
          │
          ▼
PostgreSQL · 原始证据 · 任务产物 · 执行台账
```

## 核心边界

| Shadow 持有 | 优先复用或外包 |
| --- | --- |
| 身份、规则与信任边界 | 智能体循环与规划 |
| 规范化任务、语义检查点与任务产物 | Hermes、DSH、Claude、Codex |
| 原始证据与规范化记忆契约 | Mem0、LangMem、Graphiti |
| 记忆策略、记忆代理器与上下文编译 | 向量、嵌入和图检索实现 |
| 事件、世界状态与长期调度 | Home Assistant 等设备驱动 |
| 能力注册、能力网关与执行台账 | 邮件、日历、浏览器、服务器等能力实现 |
| SRI、运行时路由、接力与升级 | 具体模型与模型服务 |
| Pulse 策略 | 聊天平台、语音栈和消息网关 |

判断标准很简单：

> **必须跨模型、跨运行时、跨设备或跨年份保持一致的状态，属于 Shadow；其余功能优先复用成熟系统。**

## v0.1 最小可行版本

第一版不追求完整的个人 AI 产品，只验证这套连续性架构是否成立。

### 核心范围

- **连续性状态**：事件、世界状态、任务、语义检查点、任务产物、原始证据与规范化记忆；
- **任务与运行时**：SRI、Hermes 适配器、DSH 适配器、上下文编译和跨运行时语义恢复；
- **记忆机制**：记忆写入策略、任务感知召回、记忆包与原始历史回溯；
- **能力与治理**：能力注册表、能力网关、规则、审批、幂等与执行台账；
- **持续运行**：事件驱动、调度、等待任务恢复，以及低成本 Pulse 机制；
- **基础设施**：PostgreSQL、pgvector、命令行、最小管理界面和本地单机部署。

### 必须通过的验证

| 场景 | 验证目标 |
| --- | --- |
| 运行时连续性 | Hermes 中断后，DSH 能从语义检查点继续同一个任务 |
| 跨运行时记忆 | 一个运行时形成的长期记忆能被另一个运行时正确使用 |
| 自主事件处理 | 没有用户提示时，事件也能更新状态、创建任务并触发执行 |
| 运行时升级 | 候选运行时可回放、灰度、晋升和回滚，而用户状态无需迁移 |
| 任务感知记忆 | 召回围绕当前任务的决策价值，并能在必要时回溯原始历史 |
| 副作用安全 | 崩溃与重试不会重复执行已经完成的现实动作 |
